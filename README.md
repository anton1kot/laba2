# laba2


## streamstats

Пакет для потокового анализа логов и событий из файлов (CSV, JSONL) с подсчётом статистики, валидацией полей и отчётами об ошибках.

## Возможности

- **Поддержка форматов**: чтение CSV и JSONL «на лету» без загрузки всего файла в память.
- **Валидация данных**: проверка обязательных полей и форматов (например, корректность даты в timestamp).
- **Агрегация статистики**: подсчёт общего количества событий, распределение по уровням (`by_level`), временны́е границы.
- **Обработка ошибок**: пропуск невалидных строк (с флагом `--skip-invalid`) и детальный отчёт о количестве пропущенных строк.
- **Гибкий вывод**: результат в `stdout` (JSON) или в файл (флаг `--output`).
- **Тестируемость**: CLI спроектирован так, чтобы его легко тестировать через `subprocess` (все примеры из тестов воспроизводимы).

## Установка

Для работы требуется Python 3.8+.

```bash
pip install -e .
```
## Быстрый старт

### Анализ одного CSV-файла

```bash
python -m streamstats analyze data.csv --format csv
```

### Несколько файлов сразу

```bash
python -m streamstats analyze events1.csv events2.csv --format csv
```

Статистика считается суммарно по всем файлам.

### Пропуск невалидных строк

Если в файле есть строки с ошибками (например, некорректная дата), используй флаг `--skip-invalid`:

```bash
python -m streamstats analyze bad.csv --format csv --skip-invalid
```

В отчёте появится поле `skipped_lines`, показывающее, сколько строк было пропущено.

### Сохранение отчёта в файл

```bash
python -m streamstats analyze data.csv --format csv --output report.json
```

При этом `stdout` будет пустым, а отчёт запишется в `report.json`.

## Формат входных данных

### CSV

Ожидается заголовок:

```text
timestamp,level,source,message
2024-01-01T10:00:00Z,INFO,app,msg1
2024-01-01T11:00:00+02:00,ERROR,db,msg2
```

Обязательные поля: `timestamp`, `level`, `source`, `message`.

### JSONL

Каждая строка — отдельный JSON-объект:

```jsonl
{"timestamp":"2024-01-01T10:00:00Z","level":"INFO","source":"app","message":"msg1"}
{"timestamp":"2024-01-01T11:00:00Z","level":"ERROR","source":"db","message":"msg2"}
```

## Структура отчёта

Пример итогового JSON:

```json
{
  "total_events": 1192800,
  "by_level": {
    "INFO": 355200,
    "DEBUG": 115200,
    "WARNING": 242400,
    "ERROR": 241200,
    "CRITICAL": 238800
  },
  "by_source": {
    "auth": 228000,
    "cache": 242400,
    "db": 242400,
    "pip": 99600,
    "billing": 238800,
    "q1": 96000,
    "q2": 12000,
    "pipka": 14400,
    "q4": 2400,
    "q3": 2400,
    "q6": 14400
  },
  "top_5_error_sources": {
    "billing": 238800,
    "pip": 99600,
    "q1": 96000,
    "pipka": 14400,
    "q6": 14400
  },
  "first_timestamp": "2026-03-01T09:90:00+00:00",
  "last_timestamp": "2026-03-02T09:04:40+00:00",
  "skipped_lines": 7200
}
```

- `total_events`: количество успешно обработанных событий.
- `skipped_lines`: количество строк, которые не удалось распарсить или валидировать.
- `by_level`: распределение событий по уровням логирования.

## Тестирование

Пакет поставляется с готовыми тестами для CLI, покрывающими:

- Анализ одного файла.
- Объединение статистики по нескольким файлам.
- Обработку повреждённых/невалидных строк.
- Вывод отчёта в файл.

Запуск тестов:

```bash
python -m pytest
```

Примеры тестовых сценариев включены в `tests/test_cli.py` и соответствуют реальным кейсам: объединение файлов, обработка повреждённых данных, проверка структуры JSON-отчёта.

## Известные ограничения
- Для CSV обязателен заголовок; если его нет, поведение может быть непредсказуемым.
